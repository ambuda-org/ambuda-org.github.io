Lisp expressions for vidyut_cli¶

examples/vidyut_cli.rs derives Sanskrit words from a short Lisp-style expression and prints the full prakriyā (step-by-step derivation) for each result.

cargo run --example vidyut_cli -- "(tiN (:dhatu (BU BvAdi)) (la~w kartari Prathama eka))"

All Sanskrit text is in SLP1 (kf = कृ, A = ा, S = श, zW = ष्ठ).

Debug builds also print debug information. Use --release to leave it out.

Interactive mode¶

With no arguments, the tool starts a prompt with line editing and history (saved in ~/.vidyut_lisp_history):

cargo run --example vidyut_cli
  • help prints example expressions, and help krt (or any other head) prints only that head.
  • quit, exit and Ctrl-D leave. Ctrl-C discards the current line.
  • An expression with unbalanced parentheses continues on the next line.
  • Errors are reported and the prompt continues. Piped input works too, without a prompt.

In the browser¶

The web app (www/index.html) has an Advanced tab with a text area. Evaluate (or Ctrl-Enter) runs the expression, and Clear empties the text area and the results. Tables are shown as HTML tables, and each full derivation is shown with the same history table as the subanta tab (a base's derivation comes first, under a "Base:" caption). Text may be SLP1 or Devanagari, and results use the script selected on the page. The expression is kept in the lisp URL parameter, so "Copy URL" shares it.

From JavaScript, vidyut.loadDhatupatha(tsvText) (optional) and vidyut.evaluateLisp(input) return { error, warnings, blocks }. See Vidyut.evaluateLisp in www/static/vidyut-prakriya.js.

Scripts: Devanagari and SLP1¶

Input can be SLP1, Devanagari, or a mix. Any atom with a Devanagari character is converted to SLP1 before it is read, so this works:

(sup (:prAtipadika राम) puM तृतीया ३)
(tiN (:dhatu (भू भ्वादि)) (la~w kartari))
(krt (:dhatu (डुकृञ् तनादि)) ण्वुल्)

Devanagari digits १-७ work as the numeric vibhakti and vacana aliases. Option names and Rust variant names (sanadi, artha, la~w, TasyaApatyam) stay ASCII.

A dhatu's upadesha may leave out its svara and anunasika markers (\, ^, ~). If the text is not in the dhatupatha for that gana, it is compared with the markers removed, and a single match is used: (:dhatu (ज्ञा क्र्यादि)) finds jYA\. If several dhatus match, the tool lists them and asks for the full upadesha. If none match, the text is used as written. Other it-markers (Y, w, q, ...) are not ignored, so write डुकृञ् (qukfY) in full.

Output is SLP1 by default. In the interactive prompt:

vidyut> output devanagari
vidyut> output slp1
vidyut> output
output: slp1

For a single expression, set VIDYUT_OUTPUT=devanagari in the environment. Only forms, terms and table labels are converted. Rule codes, debug annotations and messages stay in ASCII. Tables are aligned by display width, which can still look uneven in terminals that render conjuncts as one cell.

Using the library¶

The grammar and the evaluation are in the library module vidyut_prakriya::vyakarana_lisp_wrap (src/vyakarana_lisp_wrap.rs), which returns the results as plain data (Evaluation) and does no printing. examples/vidyut_cli.rs is the command line front end: it reads input, transliterates, and prints. To use expressions from your own program:

use vidyut_prakriya::vyakarana_lisp_wrap::*;
use vidyut_prakriya::{Dhatupatha, Vyakarana};

let v = Vyakarana::new();
let dhatupatha = Dhatupatha::from_path("data/dhatupatha.tsv")?;
let lisp = LispEvaluator::new(&v, &dhatupatha);
let result = lisp.evaluate_str("(sup (:prAtipadika rAma) puM tftIyA eka)")?;

Expression types¶

(tiN DHATU (LAKARA PRAYOGA [PURUSHA] [VACANA]))
(krt DHATU KRT KRT_OPTION*)
(tadDita PRATIPADIKA TADDHITA TADDHITA_OPTION*)
(sup PRATIPADIKA LINGA [VIBHAKTI] [VACANA])
(sup PRATIPADIKA)                        ; PRATIPADIKA is an avyaya
(samasa SAMASA_TYPE SUP SUP+ [(stri true)])
(stri PRATIPADIKA)

Building blocks:

DHATU       := (:dhatu (UPADESHA GANA) OPTION*)
             | (:nAmaDAtu PRATIPADIKA [NAMA_SANADI] OPTION*)

OPTION      := (sanadi SANADI+)        ; e.g. (sanadi Ric san)
             | (prefix PREFIX+)        ; e.g. (prefix pra upa)
             | (upasarga PREFIX+)      ; an alias of prefix
             | (antargana ANTARGANA)   ; :dhatu only, e.g. (antargana Kutadi)

PRATIPADIKA := (:prAtipadika TEXT)
             | (:avyaya TEXT)
             | (:nyAp TEXT)
             | (:krdanta DHATU KRT KRT_OPTION*)
             | (:taddhitanta PRATIPADIKA TADDHITA TADDHITA_OPTION*)

KRT_OPTION      := (artha KRT_ARTHA)    ; e.g. (artha Karta)
                 | (lakara LAKARA)      ; Satf and SAnac only
                 | (prayoga PRAYOGA)    ; Satf and SAnac only
                 | (upapada TEXT)       ; a basic pratipadika used as puM prathama ekavacana
                 | (upapada SUP)        ; a full (:sup ...) component
TADDHITA_OPTION := (artha TADDHITA_ARTHA)   ; e.g. (artha TasyaApatyam)

SUP         := (:sup PRATIPADIKA LINGA VIBHAKTI VACANA)   ; every slot is required
             | (:sup PRATIPADIKA)                         ; PRATIPADIKA is an avyaya
LINGA       := puM | strI | napuMsaka
VIBHAKTI    := praTamA | dvitIyA | tftIyA | caturTI | paYcamI | zazWI | saptamI | samboDanam
             | 1 | 2 | 3 | 4 | 5 | 6 | 7  ; numeric aliases for praTamA ... saptamI
SAMASA_TYPE := Avyayibhava | Tatpurusha | Karmadharaya | Dvigu | Ekadeshin | Bahuvrihi
             | Dvandva | SamaharaDvandva

Head aliases: :DAtu is the same as :dhatu, :kfdanta as :krdanta, kft as krt, and :tadDitAnta as :taddhitanta, taddhita as tadDita, and :namadhatu (or :nAmaDatu) as :nAmaDAtu. The pratipadika head is :prAtipadika; the older :pratipadika is not accepted. For example, (kft (:DAtu (BU BvAdi)) tavya) is (krt (:dhatu (BU BvAdi)) tavya). In Devanagari, (कृत् (:धातु (भू भ्वादि)) तव्य) works through the same aliases.

Every option is a parenthesized list that starts with its name: (name value ...). The older name(value ...) spelling is not accepted.

Suggestions in the web app¶

The Advanced tab suggests what can come next as you type, so you do not have to remember the aupadeśika form of a dhātu or the spelling of a pratyaya.

  • Dhātus. After (:dhatu (, or after (:dhatu, type part of a dhātu (SLP1 or Devanagari, without svaras) and pick it from the list. The list matches the aupadeśika form, the form as a dhātu (stu finds zwu\Y) and, for three or more letters, the artha. Picking inserts the aupadeśika form with its svaras and the gana, such as zwu\Y adAdi, and the (antargana ...) that a ghaṭādi or curādi dhātu needs. A word typed where a DHATU goes, such as (tiN aSa, offers the same list and inserts a whole (:dhatu (aSa~ kryAdi)).
  • The grammar. Each position offers only what the grammar accepts there: the heads of a list (after (:nAmaDAtu, only the pratipādika heads), krt and taddhita pratyayas, linga, vibhakti, vacana, lakāra and prayoga, sanādis, ganas, upasargas and the (artha ...) values of the krt or taddhita that was chosen.
  • Free text. The text of (:prAtipadika TEXT), (:avyaya TEXT) and (upapada TEXT), and a stem written straight after :nAmaDAtu, have no list to pick from.

Use the arrow keys to choose, Enter or Tab to insert, Esc to close, and Ctrl-Space to open the list again. Ctrl-Enter (or Cmd-Enter) still evaluates. The values come from the library (vyakarana_lisp_wrap::completions), so they are exactly the ones that the evaluator accepts.

When the caret is next to a parenthesis, that parenthesis and its partner are highlighted. A parenthesis with no partner is highlighted in red.

In a table of forms, each form is a link. Clicking it shows that form's prakriya in place of the table, under a button with the form's name and an "x". Click the button to go back to the table.

Values and quoting¶

  • Enum values (gana, lakara, prayoga, purusha, vacana, sanadi, antargana, krt, taddhita) can be an SLP1 label (BvAdi, praTama, eka) or the Rust variant name (Bhvadi, Prathama, Eka). Variant names are case-insensitive.
  • LAKARA is written as its label with anubandhas: la~w, li~w, lu~w, lf~w, le~w, lo~w, laN, viDili~N, ASIrli~N, lu~N, lf~N. (vidhi-liN and ASIr-liN have their own labels because both are li~N.) The Rust variant names (Lat, VidhiLin, ...) still work as aliases.
  • PRAYOGA is an SLP1 label only: kartari, karmaRi or BAve (the spellings Kartari and Karmani are not accepted; Bhave still is).
  • Artha values are Rust variant names and must match exactly (TasyaApatyam, Karta).
  • UPADESHA must be the dhātu's aupadeśika form exactly as in dhatupatha.tsv, including the accent marks: jYA\, not jYA.
  • Shell quoting. Wrap the whole expression in double quotes, as above. Inside double quotes the shell keeps a \ as it is, unless it comes before $, `, " or another \. Use single quotes if your expression needs one of those.
  • PURUSHA and VACANA are optional. An omitted slot expands to all of its values, and they are told apart by value: (la~w kartari Prathama) gives 3 forms, (la~w kartari dvi) gives the dual in every purusha, and (la~w kartari) gives 9. Numbers work too: 1-3 for praTama, maDyama, uttama in the first slot and 1-3 for eka, dvi, bahu in the second, so (la~w kartari 2 3) is maDyama bahu. A lone number is a purusha; to ask for one vacana, use its name (dvi).
  • Result count. If an expression derives 50 or more results, the tool prints a warning on stderr before the output.
  • Several results. The output lists every derivation the rules allow. Optional rules and both padas give more than one result, and the same form can appear twice when two derivation paths lead to it.

Nāma-dhātus¶

A :nAmaDAtu makes a verb from a pratipādika. Give the pratyaya explicitly (kyac, kyaN, kAmyac or Ric), or leave it out and the rules in 3.1 choose it. (Tests: kashika_3_1.rs, kashika_1_3.rs, kaumudi_57.rs.)

Expression Forms
(tiN (:nAmaDAtu putra kyac) (la~w kartari Prathama eka)) putrIyati
(tiN (:nAmaDAtu putra kAmyac) (la~w kartari Prathama eka)) putrakAmyati
(tiN (:nAmaDAtu lohita) (la~w kartari Prathama eka)) lohitAyati, lohitAyate (3.1.13)
(tiN (:nAmaDAtu muRqa) (la~w kartari Prathama eka)) muRqayati, muRqayate (3.1.21)
(tiN (:nAmaDAtu senA (prefix aBi)) (la~w kartari Prathama eka)) aBizeRayati, aBizeRayate (3.1.25, 8.3.65)

NAMA_SANADI is only for the pratyaya the nāma-dhātu is made with. To add a sanādi after it, use (sanadi ...). The library does not yet apply a further sanādi after a nāma-dhātu's own pratyaya, so such options currently have no effect on the forms.

krt: kṛdantas¶

(krt DHATU KRT [(artha ..)] [(lakara ..)] [(prayoga ..)] [(upapada TEXT)])

KRT is the SLP1 label of a kṛt pratyaya. Base kṛts are tried first, then uṇādi pratyayas. (Tests: kashika_1_1.rs, kashika_3_2.rs.)

Expression Forms
(krt (:dhatu (BU BvAdi)) tavya) Bavitavya
(krt (:dhatu (BU BvAdi)) kta) BUta
(krt (:dhatu (BU BvAdi)) lyuw) Bavana
(krt (:dhatu (qukf\Y tanAdi)) tfc) kartf
(krt (:dhatu (BU BvAdi)) Satf (lakara la~w) (prayoga kartari)) Bavat
(krt (:dhatu (qukf\Y tanAdi)) aR (upapada kumBa)) kumBakAra
(krt (:dhatu (qukf\Y tanAdi)) wa (upapada kumBa)) kumBakara

lakara and prayoga apply only to Satf and SAnac; they default to la~w and kartari.

Uṇādi pratyayas¶

An uṇādi pratyaya is written in the same slot as any other KRT. There is no separate head. Base kṛts are tried first, so a label that is both a base kṛt and an uṇādi pratyaya always means the base kṛt.

Expression Forms
(krt (:dhatu (qukf\Y tanAdi)) uR) kAru
(krt (:dhatu (jIva~ BvAdi)) radAnuk) jIradAnu
(krt (:dhatu (ava~ BvAdi)) wizac) aviza
(krt (:dhatu (maha~ BvAdi)) wizac) mahiza

(Tests: kashika_1_1.rs, kashika_1_3.rs.)

A valid label that does not apply to the dhatu derives nothing and prints warning: no forms were derived. For example, uR with kf\Y (rather than qukf\Y) gives no forms, because the dhatu is not the one the sutra names. A misspelled label is an error (invalid krt value).

An upapada is given as plain text, which is used as a masculine, prathamā, singular subanta. To choose the linga, vibhakti and vacana, give a full (:sup ...) component instead:

Expression Forms
(krt (:dhatu (qukf\Y tanAdi)) aR (upapada (:sup (:prAtipadika kumBa) puM dvitIyA eka))) kumBakAra

sup: subantas¶

(sup PRATIPADIKA LINGA [VIBHAKTI] [VACANA])

LINGA is required. VIBHAKTI and VACANA are optional, and an omitted slot expands to all of its values, so you can ask for one form, one vibhakti, one vacana, or the whole paradigm. They are told apart by value, and the vibhakti comes first if both are given. Numbers work in both slots: 1-7 for the vibhakti and 1, 2, 3 for eka, dvi, bahu. A number is read by position (first slot vibhakti, second slot vacana), so a lone number is a vibhakti. To ask for one vacana in all vibhaktis, use its name (dvi). (Tests: kashika_1_1.rs, kashika_2_3.rs, kashika_7_3.rs.)

Expression Forms
(sup (:prAtipadika bahu) puM praTamA bahu) bahavaH
(sup (:prAtipadika pawu) puM samboDanam eka) pawo
(sup (:prAtipadika vfkza) puM tftIyA dvi) vfkzAByAm
(sup (:prAtipadika paTin) puM praTamA eka) panTAH
(sup (:prAtipadika rAma) puM praTamA) rAmaH, rAmO, rAmAH (the three vacanas)
(sup (:prAtipadika rAma) puM 3 eka) same as tftIyA eka: rAmeRa
(sup (:prAtipadika rAma) puM 3 1) the same: numbers are VIBHAKTI then VACANA (1 eka, 2 dvi, 3 bahu)
(sup (:prAtipadika rAma) puM dvi) the dual in all 8 vibhaktis
(sup (:prAtipadika rAma) puM) the full paradigm, as an 8 by 3 table

Output shape¶

sup and tiN print the full prakriyā history only when both the vibhakti (or purusha) and the vacana are given. Otherwise they print a table of just the forms, with vacanas as columns:

(sup (:prAtipadika rAma) puM 3)                 (sup (:prAtipadika rAma) puM)
          eka     dvi       bahu                              eka     dvi    bahu
3 tftIyA  rAmeRa  rAmAByAm  rAmEH               1 praTamA     rAmaH   ...    ...
                                                ...
                                                8 samboDanam  rAma    ...    ...
  • No vibhakti: 8 rows, one per vibhakti. A sarvanāma (tad, yuzmad, asmad, sarva, ...) has no samboDanam, so its table has 7 rows. (It is detected by rule 1.1.27 in the derivation.)
  • A vibhakti but no vacana: one row.
  • A vacana but no vibhakti: one column, with all rows.
  • Several forms in one cell (variants) are joined with /, and an empty cell is -.
  • A nested base that derives several forms (such as a :taddhitanta) prints one table per form, under a ===== FORM ===== title.
  • The same holds for tiN, with the three purushas (praTama, maDyama, uttama) as the rows.
  • tiN derives each pada separately. A dhatu that takes both padas gets two tables, parasmaipada first, under ===== parasmEpadam ===== and ===== Atmanepadam =====. A dhatu with one pada (including every karmani and bhAve derivation, which is Atmanepada) gets one table and no heading. With a single purusha and vacana, each pada's prakriya is printed under its heading.
(tiN (:dhatu (ci\Y svAdi)) (la~w kartari))
===== parasmEpadam =====
         eka     dvi               bahu
praTama  cinoti  cinutaH           cinvanti
maDyama  cinozi  cinuTaH           cinuTa
uttama   cinomi  cinvaH / cinuvaH  cinmaH / cinumaH

===== Atmanepadam =====
         eka     dvi                 bahu
praTama  cinute  cinvAte             cinvate
maDyama  cinuze  cinvATe             cinuDve
uttama   cinve   cinvahe / cinuvahe  cinmahe / cinumahe

Avyayas¶

An avyaya takes no linga, vibhakti or vacana. Mark a plain word with (:avyaya TEXT). A krdanta whose pratyaya makes avyayas (such as ktvA) is detected automatically, and so is a taddhitanta whose pratyaya makes avyayas by 1.1.38 (such as cvi~, tasil, Sas).

Expression Forms
(sup (:avyaya ca)) ca
(sup (:krdanta (:dhatu (BU BvAdi)) ktvA)) BUtvA
(sup (:tadDitAnta (:prAtipadika Sukla) cvi~)) SuklI

nyāp stems¶

A plain (:prAtipadika TEXT) stem is not marked as ending in a nyāp-pratyaya (ṅī, āp, ūṅ), so rules that need that, such as the su-lopa of 6.1.68, do not apply. Use (:nyAp TEXT) for a stem that ends in one. This is the nyap(...) helper in the Kaumudi tests (kaumudi_09.rs).

Expression Forms
(sup (:nyAp ramA) strI tftIyA eka) ramayA
(sup (:nyAp nadI) strI praTamA eka) nadI
(sup (:prAtipadika nadI) strI praTamA eka) nadIH (compare lakzmIH)
(sup (:nyAp strI) strI praTamA eka) strI

A stem derived with (:stri ...) is already marked this way.

samasa: compounds¶

(samasa SAMASA_TYPE SUP SUP+ [(stri true)])

Each pada is a full (:sup ...) component. For an avyaya first member (as in an avyayībhāva), use (:sup (:avyaya TEXT)). The type is a Rust variant name, matched case-insensitively. (Tests: kashika_1_1.rs, kashika_2_2.rs.)

Expression Forms
(samasa Tatpurusha (:sup (:prAtipadika rAjan) puM zazWI eka) (:sup (:prAtipadika puruza) puM praTamA eka)) rAjapuruza
(samasa Tatpurusha (:sup (:tadDitAnta (:prAtipadika Sukla) cvi~)) (:sup (:krdanta (:dhatu (qukf\Y tanAdi)) ktvA))) SuklIkftya
(samasa Avyayibhava (:sup (:avyaya upa)) (:sup (:prAtipadika agni) puM praTamA eka)) upAgni
(samasa Bahuvrihi (:sup (:prAtipadika UQa) puM praTamA eka) (:sup (:prAtipadika raTa) puM praTamA eka)) UQaraTa

Chaining¶

A kṛdanta or taddhitānta can be the base of another derivation. Use (:krdanta ...) or (:taddhitanta ...) where a pratipādika is expected. (See create_krdanta and create_taddhitanta in test_utils, used by kashika_1_2.rs.)

Expression Forms
(tadDita (:taddhitanta (:prAtipadika upagu) aR) tva) Opagavatva
(tadDita (:krdanta (:dhatu (qukf\Y tanAdi)) tfc) tva) kartftva
(tiN (:nAmaDAtu (:krdanta (:dhatu (aSa~ BvAdi)) lyuw) kyac) (la~w kartari Prathama eka)) aSanIyati, aSanAyati

If a nested :taddhitanta derives several forms, the outer derivation is applied to each of them and every result is printed:

Expression Forms
(tadDita (:taddhitanta (:prAtipadika yuvan) izWan) tva) yavizWatva, kanizWatva
(sup (:taddhitanta (:prAtipadika yuvan) izWan) puM praTamA eka) yavizWaH, kanizWaH

(:stri PRATIPADIKA) is the feminine stem derived by stri, usable where a pratipādika is expected (PRATIPADIKA := ... | (:stri PRATIPADIKA)). The library has no stryanta pratipādika, so the example derives the feminine form and passes its text as a stem that already ends in a nyāp-pratyaya. Each distinct feminine form becomes one base:

Expression Forms
(sup (:stri (:prAtipadika nara)) strI tftIyA eka) narayA
(sup (:stri (:prAtipadika deva)) strI saptamI eka) devAyAm
(sup (:stri (:krdanta (:dhatu (BU BvAdi)) tavya)) strI zazWI eka) BavitavyAyAH

Only sup and samasa were checked with this base. Use strI as the linga.

A subanta can be a base for a kṛdanta's upapada, and for the padas of a samasa, through the (:sup ...) component (see above). It cannot be the base of a krt or tadDita, since a subanta is a finished pada.

How a base is derived¶

A (:krdanta ...) or (:taddhitanta ...) base is derived on its own before the expression that uses it starts:

  1. The base's rules run to completion in a separate derivation that contains only the base's own terms. Nothing around it can affect it. For example, in a samasa a member is not affected by the members next to it.
  2. The base's terms are not given sandhi, the rules of 8.1, or the rules of the tripāḍī (8.2 - 8.4), since those belong to a finished pada. The base also does not decide the linga of the outer derivation.
  3. The outer derivation then starts from the base's terms, with all their tags and their history, and adds its own pratyaya. The tadDita, sup or samasa expression is the command, and it runs sandhi and the tripāḍī once at the end.

So (tadDita (:krdanta (:dhatu (dfha~ BvAdi)) kta) izWan) first derives dfh + i + ta, then adds izWan, and dfh becomes dfQ only when the tripāḍī runs at the end. Rules that were already applied inside the base (such as guṇa) are not applied again to the same terms. Rules that the new pratyaya triggers, such as the ṭi-lopa for izWan, still apply to the base's terms.

Chains that work through sup:

Expression Forms
(sup (:krdanta (:dhatu (qukf\Y tanAdi)) tfc) puM praTamA eka) kartA
(sup (:taddhitanta (:prAtipadika upagu) aR) puM praTamA eka) OpagavaH

Using a derived text as a plain stem¶

(:prAtipadika EXPRESSION) derives any tiN, krt, tadDita, sup, samasa or stri expression and uses each distinct resulting text as a basic stem. This differs from :krdanta and :taddhitanta, which keep the derivation history, so later rules still see a krdanta:

Expression Forms
(tadDita (:krdanta (:dhatu (dfha~ BvAdi)) kta) izWan) dfhitezWa, dfQezWa
(tadDita (:prAtipadika (krt (:dhatu (dfha~ BvAdi)) kta)) izWan) dfhitizWa, draQizWa
(sup (:prAtipadika (krt (:dhatu (BU BvAdi)) tavya)) puM 1 eka) BavitavyaH

An expression with several results becomes several stems, and each is derived in turn. Prefer :krdanta and :taddhitanta when the base's own derivation matters.

When a prakriyā is printed with its history, the derivation of the stem comes first, then a marker line, then the derivation built on it:

dfhitizWa
---------------------------
3.2.102    | dfh + kta
...
1.2.46     | dfh + i + ta
1.2.45     | dfhita
           | ==== base derived: dfhita ====
1.2.45     | dfhita
5.3.55     | dfhita + izWan
...

The history is only expanded in the printed output, so the stem is matched by its text. Tables (which show only forms) are unaffected.

Errors and limits¶

  • An unknown enum value, option or head is an error and exits with status 1, e.g. error: invalid krt value: nosuch.
  • If a derivation produces nothing, the tool prints warning: no forms were derived. and exits 0.
  • A :nAmaDAtu base must be a plain pratipadika or a :krdanta. A :taddhitanta base is not supported by the library, and the tool reports an error instead of passing it on.
  • There is no require option. Results are never filtered.
  • krt and tadDita take no sanadi, prefix or upasarga option. Put them on the (:dhatu ...) inside.
  • sup needs a linga unless the base is an avyaya. In samasa and nested (:sup ...), the vibhakti and vacana are required too.
  • A samasa needs at least two padas. (stri true) marks the samasa as feminine.
  • (:dhatu ...) always needs a gana. (antargana ...) is only for :dhatu.
